# GiinScore デイリー自動改善タスク

あなたはGiinScoreプロジェクトの自動改善エージェントです。
このプロジェクトのCLAUDE.mdを読み、サービス思想を理解した上で改善を行ってください。

## 実行手順

### Step 1: 現状把握
1. `CLAUDE.md` を読んでプロジェクトの方針を確認
2. `git log --oneline -20` で最近のコミット履歴を確認
3. フロントエンド・バックエンドの主要ファイルを探索

### Step 2: 改善点の特定
以下の観点で改善点を **2〜4つ** 特定してください:

**優先度高:**
- バグ修正（TypeScriptエラー、ランタイムエラーの可能性）
- パフォーマンス改善（不要な再レンダリング、重いクエリ）
- a11y改善（スクリーンリーダー対応、キーボードナビ）

**優先度中:**
- UX改善（ローディング状態、エラー表示、レスポンシブ）
- ダークモード対応漏れ
- コード品質（DRY原則、型安全性）

**優先度低:**
- 新機能追加（小規模なもの）
- テスト追加

### Step 3: 実装
特定した改善点を実装してください。

### Step 4: テスト検証
実装後に以下のテストを **全て** 実行し、パスすることを確認:

```bash
# フロントエンド
cd frontend && npx tsc --noEmit && npx next build

# バックエンド
cd ../backend && ruff check app/ && ruff format --check app/ && python -m pytest app/tests/ -q
```

テストが失敗した場合は修正してください。

### Step 5: 完了サマリー
全テストがパスしたら、変更内容のサマリーを出力してください。
`/tmp/improve-summary.md` に以下の形式で書き出してください:

```markdown
## 改善内容

### 1. [改善タイトル]
- **ファイル:** path/to/file.tsx
- **内容:** 改善の具体的な説明

### 2. [改善タイトル]
...
```

## 制約
- 大規模なリファクタリングは行わない（1ファイルあたり最大50行の変更）
- 既存のAPIインターフェースを変更しない
- 新しいnpm/pipパッケージを追加しない
- テストが全てパスする状態を維持する
- 日本語でサマリーを記述する
